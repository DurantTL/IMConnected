# Events, website navigation and editorial queues

## Public homepage

The **Coming together** event spotlight appears above the latest stories when published events exist. It shows up to six events, ordered by event date with undated events last. Past events are omitted using the conference's America/Chicago calendar day, including daylight saving time. Ordinary announcements, unpublished stories and draft-only stories never enter this rail. Publish an Event with its first photo to include a full-aspect flyer; stored photo zoom/pan is retained but is not applied to this flyer.

With two or more events, the spotlight advances every seven seconds while visible and idle. Previous/Next buttons, numbered event choices, swipe/scroll and arrow keys on the focused rail provide manual navigation. A small icon-only pause/play button sits beside the previous/next arrows above the rail, so it comes before the slides in the Tab order (its label reads "Pause automatic advance" or "Resume automatic advance"); a pause stays until Resume is selected, and a horizontal swipe on the event track also pauses it. There is no separate text button or status notice, and "Event N of M" is read by screen readers only. The spotlight is deliberately compact (issue #161: a 56px heading row, flyers capped at 210px and 150px on phones on a flat light-tint panel with no gradient or shadow, no "/ 01" index beside "Coming up", no slack under the slide; from 1200px the numbered choices share the heading row; the summary is clamped to 3 lines, 2 on a phone, with the full text still in the page and shown in full where `line-clamp` is unsupported; a 48-character title is at most 2 lines at 1280px and 3 at 390px). At 390x844 with one event, its title, date and Explore button end at about 760px, inside the first screen. Hovering, focus inside the spotlight, a hidden tab and scrolling it offscreen suspend rotation. Reduced motion disables automatic advance and the toggle stays visible but disabled, labelled "Automatic advance off". Without JavaScript, all event cards remain readable in the scrollable rail. One event needs no controls; no upcoming events hides the spotlight. See the [publication redesign guide](PUBLICATION-REDESIGN.md) for the new brand and layout. The subtle card entrances, navigation underline and expanding phone menu take movement ideas from [durant.xyz](https://durant.xyz/); they copy no portfolio content or dependencies. Reduced motion disables spatial entrance and menu transitions and makes rail navigation instant. Content never waits hidden for an animation script.

## Website menu

Administrators open **Website menu** at `/admin/navigation`. Editors cannot read or change these settings.

- Change labels, public addresses, visibility and order. Use the arrow buttons or numbered positions. Clear both a label and address to remove its row; fill a blank row to add a link.
- Keep between one and twelve links, with at least one visible. Addresses accept a root-relative public path or full HTTPS URL. Private `/admin` and `/api` destinations, credentials and executable URL schemes are refused.
- **Save website menu** updates desktop and phone navigation together. **Restore default menu** restores the central section links. Search and Submit a Story remain separately available.
- The default menu ends with **Issues** (`/issues/`, the newsletter issue browser, issue #99). Menus are stored as a whole, so a menu an administrator already saved is not changed: it keeps exactly its saved links and does not gain Issues on its own. Add it with a blank row (label `Issues`, address `/issues/`) or use **Restore default menu**. A site that never saved a menu shows Issues at once. The pages work either way; hiding the link only removes it from the menu.
- Two administrators cannot silently overwrite each other: a stale save returns a conflict and reloads the current configuration for review. Changes are audited without storing labels or addresses in the audit entry.

The **Newsletter signup link** field on the same screen holds one optional full `https://` page address (empty by default; `http://`, relative and `/admin` or `/api` addresses are refused and the field is redisplayed with an inline error). It is saved and audited with the menu (the audit entry lists the changed field names, never the address), and **Restore default menu** keeps it. When set, every story page ends with a "Get IMConnected in your inbox" button (same tab) beside the Submit a Story call to action; when empty only the submit call to action shows. Public `GET /api/navigation` carries it as the additive `newsletterSignup` string (empty when unset). Story pages also have a JavaScript-only **Print this story** button and a print stylesheet that leaves just the title, byline, photos with captions and text. Migration 032 adds the column.

Migration 023 stores the singleton configuration in the existing SQLite database. The section/category definitions still live in `src/lib/site.ts`; menu changes do not rename sections or move stories. Saving invalidates the origin's page cache. Previously cached or prerendered pages refresh their links from public `GET /api/navigation`, which returns only visible items and their configuration version, without cookies or private settings. Without JavaScript, prerendered pages retain the build's default navigation. An already cached page can retain its prior links until refresh; the server's next uncached render uses the saved menu.

## Separate editor screens

**Stories** (`/admin`), **Announcements** (`/admin/announcements`) and **Events** (`/admin/events`) each have their own draft list, open count and New action. Status, section and AI-agent source filters remain available. **All drafts** provides a combined oversight view. New announcement/event actions create typed In review drafts, not live content. Changing a draft's type in Story settings moves it to the corresponding queue after saving. Publishing and existing agent/Studio contracts retain their human review rules.

## Module quick access

In a modular draft's Content panel, the module library offers Writing, Images & video, Layout, Links and Favorites categories plus search. Open **Customize quick access** to choose Favorites. Those choices belong to this browser's local storage and persist across reloads; they do not modify, autosave or publish the draft. If storage is blocked, the editor explains that preferences last only for the current page. **Clear filters** returns to all eleven module types. Existing module content, ordering and undo history are unaffected by library preferences.

## Verification

It starts an isolated built server, seeds disposable synthetic data and blocks external browser requests.
