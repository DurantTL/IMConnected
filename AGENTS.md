# AGENTS.md: IMConnected

Instructions for AI coding agents (Codex, Claude) working in this repo.

## Stack
- Astro 7 (`output: 'static'` + `@astrojs/node` standalone). Pages are prerendered, and only `src/pages/api/submit.ts`, `src/pages/api/publish.ts`, `src/pages/api/stories.ts` (`/api/stories`), `src/pages/api/confirm.ts`, `GET /media/*` (`src/pages/media/[...path].ts`), the public story pages and feeds (`/`, `/stories/<slug>/`, `/<section>/`, `/<section>/<area>/`, `/stories.json`, `/rss.xml`; epic #25 step 2), `/images/stories/*` (only reached when the static file is missing), `/api/agent/*`, `/admin*` and `/api/admin/*` run on the server (`prerender = false`). `/submit/`, `/search/`, `/confirm/` and the 404 page are still prerendered.
- Content: `src/content/stories/*.md`, with the schema in `src/content.config.ts`.
- Search: Pagefind runs after `astro build` (`npm run build`). Article bodies are marked `data-pagefind-body`. Because story pages are no longer prerendered, the build also prerenders copies under `/search-source/<slug>/` (`src/pages/search-source/`) for Pagefind to index; `scripts/prune-search-source.mjs` deletes them from `dist/client` right after indexing, and `/search` rewrites result links back to `/stories/<slug>/`. SQLite FTS5 replaces all of this in step 3.
- Editor dashboard: `/admin*` and `/api/admin/*` are server-rendered and guarded by `src/middleware.ts` (session, 2FA state, Origin check, no-store/noindex headers). The middleware must return immediately for every other path: no database, cookies or session. The one exception is the in-memory page cache lookup for the few GET paths in `publicCacheKey()` (`src/lib/public-cache.ts`). See epic #7.
- Deploy: Docker image built by `.github/workflows/docker.yml` and pushed to GHCR.

## Rules
- Section and category definitions live only in `src/lib/site.ts`. If you change them, also update `.pages.yml`.
- When the content schema changes, keep `.pages.yml`, `src/lib/submission.ts` (frontmatter writer), `src/lib/feed.ts` (the `/stories.json` and `/rss.xml` feeds) and the README example in sync. Treat `/stories.json` fields as a public contract: add fields freely, but don't rename or remove one without bumping its `version`.
- Never render submitted text as raw HTML. `textToMarkdown()` in `src/lib/submission.ts` must keep escaping `< > & [ ]`.
- Submissions: `/api/submit` creates a `drafts` row (default `SUBMISSIONS_TO=dashboard`) and makes no GitHub call; `SUBMISSIONS_TO=github` is the old pull-request path, to be removed in a follow-up. If the database is down it answers 503 rather than lose the story. `/api/publish` (Studio) still commits straight to `main` and also records a `published` draft (source `studio`).
- AI agent API: `POST /api/agent/stories` (and `GET /api/agent/sections`) lets the communication director's AI agent send stories. Bearer `AGENT_API_TOKEN` (32+ characters, constant-time compare; 503 when unset or short), machine-to-machine, no CORS, not under `/api/admin`. It only ever creates a `new` draft (source `agent`) or updates one that is still `new` and untouched by an editor (idempotent by `sourceUrl`; otherwise 409), with the same escaping as dashboard drafts, `data:` photos only (never fetches a URL), 60 requests per hour. It cannot publish, reject or edit anything else. `GET /api/stories` is the authenticated list IMConnected Studio imports from (same `PUBLISH_TOKEN` and `PUBLISH_ORIGINS` as `/api/publish`); it never includes submitter contact details.
- Storage: published stories stay Markdown files in git (publishing is a commit to `main`). A small SQLite database (`node:sqlite`, in `DATA_DIR`, a Docker volume at `/data`) holds editor accounts, sessions, drafts and the audit log, and (until step 4 of epic #25) a mirror of the published stories and their photo records. Schema changes are new numbered files in `src/lib/db/migrations/`; never edit an applied one. Don't add another datastore.
- Stories in the database (epic #25): migration 011 adds `stories` and `story_photos`. **Until step 4 the `stories` table is only a mirror of git**: `src/lib/story-sync.ts` refills it from the built content collection (baked into the server bundle, so it works in the image where the Markdown sources do not exist) on the first database open after a start, copying photos from `dist/client/images/stories/` into `DATA_DIR/media/stories/<slug>/<sha256>.<ext>`. It is idempotent, runs in the background inside try/catch (retried after about a minute on failure, at most 5 passes; no file I/O inside a write transaction; a photo is re-verified after a new build via a marker over the exact files the stories reference). Edit stories in git (or the dashboard) as before; do not write to `stories` by hand. `GET /media/*` serves only `DATA_DIR/media` files that are jpg/png/webp, refuses traversal (encoded, double-encoded, backslash, absolute, symlinks), and the middleware does not touch it. Use `src/lib/story-store.ts` for access.
- Public pages from the database (epic #25, step 2 of 5): the home page, story, section and area pages, `/stories.json` and `/rss.xml` are rendered on the server through `src/lib/public-stories.ts`. **Fresh start rule:** the table is read only after the mirror has completed a pass in this process (`storySyncDone()`); before that, and whenever the table can't be read, pages are built from the built collection (what the prerendered pages used, minus slugs the dashboard unpublished), so a reader never sees a missing or empty page; the first public request starts the mirror, and completing it clears the cache. Rendered pages and feeds are cached in memory (`src/lib/public-cache.ts`: at most 300 entries, 10 minute TTL, keyed by `publicCacheKey()`, only 200 responses, a render that started before an invalidation is not stored); every `story-store.ts` write calls `invalidateStories()`, and so do the dashboard's unpublish (which also calls the store's `unpublishStory` and records a hold in `story_holds`, migration 012) and publish handlers, so an unpublished story is a 404 from this server at once (Cloudflare or a browser may keep the page they hold for up to about 6 minutes: `max-age=60` plus `stale-while-revalidate=300`). **Never revive an unpublished story on republish:** the mirror and the build hold only its old text, so a hold (`story_holds`, rule in `src/lib/story-holds.ts`, used by both the sync and the build fallback) keeps it hidden until the running image contains the republish commit. The republish handler records that commit in the hold (`republish_sha`); the image's commit list is `/app/.build-commits` (written by `.github/workflows/docker.yml`: `git log -200 --format=%H`, copied by the Dockerfile; `BUILD_COMMITS_FILE` overrides it). No republish recorded: hidden. Commit list contains it: released and the build's text goes live. Non-empty list without it: hidden. No list (local or dev build): released only when the build marker differs from the one recorded at unpublish (a NULL marker never counts as different). Anything that can't be evaluated keeps held stories hidden. Responses carry `Cache-Control: public, max-age=60, stale-while-revalidate=300` (404s `no-store`). Until step 4 publishing still commits to git, so a newly published story reaches these pages only after the next image deploy (as before); do not move publishing off git here. Photo addresses on these pages are `/media/...`; `/images/stories/...` still works (static file, else a 301 to the `/media/` copy), because sent newsletters link to it. Keep the markup, URLs, SEO tags and the `/stories.json` shape and `version` unchanged.
- Before finishing, run `npm run build`. It must pass with no errors.
- To test submissions: `node scripts/mock-github.mjs` plus `GITHUB_API_URL=http://localhost:4010`.

## Issues and Claude Code
- `codex-ready` marks an issue with acceptance criteria that an agent may build. `needs-decision` and `needs-human` mark issues blocked on a person and are never `codex-ready`.
- If a requirement is unclear and the answer would change behavior, stop, add the `needs-decision` label, and write down the question.
- Claude Code's subagents live in `.claude/agents/`; its routing rules are in `CLAUDE.md`.

## Data and human gates
- Use synthetic data only in sample stories, tests, screenshots and commits. Submitter contact details (email, phone) live only in the database and the editor-only panel in `/admin` (and in the PR description when `SUBMISSIONS_TO=github`); never copy them into story files, issues, logs, prompts, commits, or the emails sent to editors.
- Agents never connect to the production database or create real accounts; test against a throwaway `DATA_DIR` with synthetic data and delete it.
- The AI agent can only create `new` drafts, or update a draft that is still `new` and untouched, through `/api/agent/stories`. Publishing, rejecting and editing anything else stay a person's actions. Agents building this repo must never call the real `/api/agent/*` endpoints or use or ask for `AGENT_API_TOKEN`; test only against a local build with a made-up token.
- Only a person may publish or reject a draft in the dashboard (and merge or close a submission PR on the old `SUBMISSIONS_TO=github` path), merge any PR, deploy or pull a new image on the server, change the GitHub token or other secrets, or send a newsletter. Agents may prepare reviewable changes but must not cross those gates.
- The Studio "Publish to IMConnected" button (`/api/publish`) is a person's action. Agents must never call `/api/publish` against the real site, and must never use or ask for `PUBLISH_TOKEN` (the same token guards `GET /api/stories`). Test it only against `scripts/mock-github.mjs` with a made-up token.
- Never log submitter email addresses or phone numbers (log the draft id or PR number instead). Editor notification emails carry only the escaped title and church plus a link. Agents must never send real email: test with `RESEND_API_KEY` unset, or point `EMAIL_API_URL` at a local mock of the Resend endpoint. Use only Cloudflare's documented Turnstile test keys, or `TURNSTILE_VERIFY_URL` pointing at a local mock.

## Editorial voice (for any sample or generated copy)
Warm but professional, faith-oriented without being overly formal, inverted-pyramid news style. Never invent names, events, quotes or facts about real people or churches.
